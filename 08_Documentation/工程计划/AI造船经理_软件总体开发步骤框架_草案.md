## 产品建设目标

建设一个面向船舶建造项目经理的 AI 管理平台，实现项目数据统一接入、知识管理、智能分析、任务跟踪、风险预警和项目决策辅助。

## 一、软件总体建设路线

分为八个阶段，逐步形成完整产品。

### 1. 阶段一：产品规划与需求定义

- 明确目标用户和核心使用场景
- 梳理船舶项目管理业务流程
- 确定第一期产品范围
- 制定产品路线图和优先级
- 由 GPT 主导设计

### 2. 阶段二：总体架构与技术设计

- 系统总体架构
- 数据架构与统一数据入口
- AI 模型和智能体架构
- 权限、安全、审计机制
- 模块接口和技术规范
- 形成架构基线

### 3. 阶段三：基础平台建设

- 用户、组织、角色和权限
- 项目管理基础数据
- 数据导入和统一管理
- 数据库及索引
- 日志、审计和运行监控

### 4. 阶段四：核心业务模块开发

- 项目知识库
- 邮件智能管理
- 项目任务与计划管理
- 风险和问题管理
- 会议纪要和工作报告
- 项目进度与状态看板

### 5. 阶段五：AI 智能能力建设

- 自然语言问答
- 历史项目经验检索
- 邮件和文档智能分析
- 任务、风险、待办自动提取
- 项目异常识别和预警
- AI 辅助决策

### 6. 阶段六：系统集成与可视化

- AVEVA Marine 模型数据接入
- GLB/glTF 轻量化模型展示
- 项目管理看板
- 外部软件和数据接口
- 跨模块数据关联

### 7. 阶段七：系统测试与独立验收

- 功能测试
- 安全测试
- 数据准确性测试
- AI 结果质量测试
- 性能与稳定性测试
- 用户实际场景验证
- 由 GPT 独立验收，作为阶段关闭依据

### 8. 阶段八：部署上线与持续迭代

- 正式环境部署
- 用户培训
- 数据初始化
- 运行监控
- 问题处理
- 版本迭代和功能扩展

## 二、软件模块总体结构

建议将 AI造船经理规划为六大业务中心，外加统一平台与安全运行底座：

| 模块 | 内容 |
|---|---|
| AI造船经理统一平台 | 统一用户、项目、权限、数据和工作入口 |
| 项目数据中心 | 邮件、图纸、文件、模型、业务数据 |
| AI知识中心 | 知识库、检索、经验、智能问答 |
| 项目管理中心 | 任务、计划、进度、问题、风险 |
| AI智能体中心 | 邮件助手、周报助手、项目分析助手 |
| 船舶数字模型中心 | AVEVA 模型、舱室、甲板、轻量化展示 |
| 经营决策中心 | 项目看板、风险预警、管理驾驶舱 |
| 统一安全与运行底座 | 数据隔离、权限管理、审计追溯、本地部署、AI 调用控制 |

产品原则：避免做成一堆互不关联的 AI 小工具。最终应形成统一体系——项目数据是基础，知识库是记忆，业务模块是执行，AI 智能体是助手，项目驾驶舱是管理入口。

后续每一个工程 Phase 都应明确：属于哪个业务中心、解决什么业务问题、依赖哪些基础能力、怎样验收。

## 四、每个阶段必须遵守的交付制度

每个阶段都经过以下闭环：

1. GPT 批准设计方案
2. GPT 发布开发任务书
3. Grokbot 指挥 Cursor 开发
4. Cursor 提交代码和测试证据
5. 代码推送 GitHub 指定分支
6. GPT 读取实际代码并独立审查
7. 发现问题则集中整改
8. GPT 批准阶段关闭

阶段关闭必须有：

- 版本号和 Git HEAD
- 完整代码差异
- 自动化测试结果
- SHA256 和交付清单
- 安全及数据隔离证据
- 已知问题和遗留事项
- GPT 独立验收结论
