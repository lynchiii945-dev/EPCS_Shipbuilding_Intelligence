# 数据库初始化说明

> EPCS Shipbuilding Intelligence — SQLite 初始化（Phase 1.1）
> 更新：2026-11-12

---

## 1. 数据库文件

- 路径：`01_Data/epcs_intelligence.db`
- 大小：8192 bytes（空库）
- 类型：**新系统独立数据库**，与旧系统 `mail_index.db` / `mail_ledger.db` 完全无关

## 2. 实测版本（Phase 1.1 空库记录，不是当前迁移后的状态）

| 项 | 值 |
|---|---|
| SQLite | **3.53.1** |
| Python sqlite3 模块 | 2.6.0 |
| FTS5 | 可用（virtual table 可建） |
| FTS5 trigram 中文检索 | "集控台" 命中 1 |
| 读写权限 | 临时表 写入/删除 成功 |

## 3. 初始化脚本

- 位置：`01_Data/scripts/init_db.py`
- 用法：
  - `python 01_Data/scripts/init_db.py` — 幂等迁移 + 自检
  - `python 01_Data/scripts/init_db.py --check` — 只检查不迁移
  - 追加 `--db <路径>` 可指向临时库
- 行为：建表交给 `01_Data/migrations`。不再要求业务表数量为 0。FTS5 trigram 仍用「集控台」自检。实体表数量使用 `PRAGMA table_list`，条件为 `type='table' AND name NOT LIKE 'sqlite_%'`。

## 4. 迁移脚本位置

- `01_Data/migrations/` — 幂等迁移运行器。当前只含统一资料入口切片用到的表。
- `01_Data/scripts/` — 初始化与入口命令。入口说明见 `01_Data/intake/说明.md`。

## 5. 检索策略（前置结论）

沿用 Phase 0 审计结论：SQLite FTS5 默认 `unicode61` 不切分中文，**必须用 `trigram` 分词器**（实测失败/成功已验证）。数据库设计时相关表建 FTS 索引强制 trigram。

## 6. 安全约束

- 不导入旧数据、邮件、项目文件。
- 不连接旧生产数据库。
- schema 变更永远通过 migrations 幂等脚本，不手工改库。
