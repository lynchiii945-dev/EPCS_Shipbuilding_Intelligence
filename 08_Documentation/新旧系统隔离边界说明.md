# 新旧系统隔离边界说明

> 定义 EPCS 新系统与旧知识库 `D:\ALLAN\个人知识库` 之间的严格边界。
> 更新：2026-11-12

---

## 1. 物理路径边界

| 系统 | 根路径 |
|---|---|
| **新系统（本）** | `D:\ALLAN\EPCS_Shipbuilding_Intelligence` |
| **旧系统** | `D:\ALLAN\个人知识库` |

两个目录**完全独立**，无共享子目录、无符号链接、无硬链接。

## 2. 允许的行为（旧系统侧）

| 动作 | 约束 |
|---|---|
| 只读参考 | ✅ 允许（如复用评估，见下） |
| 技术复用评估 | ✅ 允许，但仅**产出分析文档**，不读取真实邮件正文 |

## 3. 禁止的行为（硬边界）

| # | 禁止项 |
|---|---|
| 1 | 修改旧系统任何文件 |
| 2 | 复制旧系统 110+ 个历史脚本到新系统 |
| 3 | 复制旧系统 15 个数据库备份 |
| 4 | 复制旧系统重复卡片（邮件卡片 / 周报 / 日报等） |
| 5 | 直接调用旧系统生产数据库（mail_index.db / mail_ledger.db 等） |
| 6 | 读取未授权真实邮件正文 |
| 7 | 将旧系统作为新系统的运行依赖 |

## 4. 环境安全边界（全局）

- 不使用、不启动、不配置 **Ollama**
- 不安装未经批准的软件或 Python 依赖
- 不连接邮箱、微信及外部账号
- 不调用外部 AI 处理本地资料
- 不上传任何本地文件
- 不修改任何原始业务资料

## 5. 数据流方向（仅参考）

```
旧系统 (个人知识库)     [只读参考]     新系统 (EPCS)
        │                              │
  ┌─────┴─────┐            ┌───────────┴─────────┐
  │ 只读评估   │ ──分析文档──▶ │  独立 Vault / Data  │
  │ 不拷贝     │              │  独立 DB / Git     │
  └───────────┘              └────────────────────┘
```

## 6. 验证方式

每次开发前确认新系统工作目录与任何旧路径无交集。任何"复用旧能力"的诉求必须先提交《技术复用评估》，经架构师审批后方可引入（且以"重写轻拷贝"为原则）。
