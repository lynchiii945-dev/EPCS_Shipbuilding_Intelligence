# Phase1.2 数据模型设计任务书

> 占位任务书 —— 供系统架构师审核本阶段报告后批准，启动 Phase 1.2。
> 更新：2026-11-12

---

## 一、背景

Phase 1.1 已建立独立项目空间、新 Vault、独立 SQLite 空库与 Git 基础。本任务书为 **Phase 1.2 的启动前置说明**，尚不执行。

## 二、Phase 1.2 目标

设计 EPCS 系统**首个正式数据模型**（SQLite schema），覆盖四阶段与实体关系。

## 三、建议建模范围（评审用，可调整）

1. **核心实体**：项目(Project)、设备(Equipment)、专业(Discipline)、区域(Area)、图纸(Drawing)、文档(Document)。
2. **EPCS 四阶段**：Engineering / Procurement / Construction / Commissioning 的阶段标签与状态。
3. **业务对象**：任务(Task)、风险(Risk)、决策(Decision)、会议纪要(Meeting)、邮件(Email)。
4. **实体关系**：项目↔设备↔专业↔区域↔图纸多维关联；对象↔来源追溯。
5. **检索**：所有文本表配 reversible/可复用的 FTS5 **trigram** 索引。

## 四、Phase 1.2 待定（评审要点）

- 表格清单与主外键。
- 元数据维度（阶段/专业/区域/角色）枚举与规范化。
- 迁移脚本命名与幂等版本控制。
- 是否引入版本追踪（内容 hash）与软删除。
- 权限/多角色字段预留（Phase 后期）。

## 五、范围外（本阶段不做）

业务功能开发、旧数据迁移、DWG SDK 安装、邮件/会议/微信接入、业务自动化、计划/风险/问题管理功能——**均留待后续 Phase，且需架构师另行审批。**

## 六、验收

- 产出 EPCS 数据模型设计文档。
- 产出首个 `migrations/001_init.sql`（幂等）。
- 空库升级为含设计表（但不含业务数据）的新库。
- 通过系统架构师评审。
